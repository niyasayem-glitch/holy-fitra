# Download and install Holy Fitra

## Source repository

The source repository is [`niyasayem-glitch/holy-fitra`](https://github.com/niyasayem-glitch/holy-fitra). Clone the main branch with:

```bash
git clone https://github.com/niyasayem-glitch/holy-fitra.git
cd holy-fitra
```

The repository is the most complete distribution because it contains the Python-compatible development tools, the native compiler sources, the C++17 bootstrap compiler, native kernels, Android Gradle modules, tests, and CI definitions.

## Linux or Termux CLI

The CLI requires Python 3 and uses Clang/LLVM for native compilation. On Termux, install the native toolchain without `sudo`:

```bash
pkg update
pkg install python clang llvm cmake coreutils findutils git
bash termux-build.sh install-v1
```

The installer places the user-local launcher under `$HOME/.local/bin`. Add that directory to `PATH` if necessary:

```bash
export PATH="$HOME/.local/bin:$PATH"
holyfitra doctor
holyfitra capabilities
```

For a development checkout, the Python package can also be installed into the user environment:

```bash
python3 -m pip install --user -e .
```

The native compiler can then be exercised with:

```bash
holyfitra init my-ai-project --template ai
holyfitra check my-ai-project
holyfitra test my-ai-project
holyfitra build my-ai-project -o my-ai-project/build/app
holyfitra run my-ai-project
```

The AI template is deterministic and local by default. Provider-backed operations are explicit:

```bash
holyfitra ai providers
holyfitra ai chat "Explain this compiler diagnostic" --provider PROVIDER_NAME
holyfitra ai generate-fitra "Write a checked scalar function" -o generated.hf --provider PROVIDER_NAME
```

Do not place provider API keys in the repository. Configure them in the user environment according to the provider-neutral AI API documentation.

## Android Workbench APK

The main branch continuously builds an arm64-v8a Android Workbench. The final verified debug APK is attached to the task response and can be installed with:

```bash
adb install -r android-app-debug.apk
```

The APK is debug-signed for testing. It is not a production-signed store release. The production release APK generated by CI is intentionally unsigned and must be signed with the deployer’s own key.

To retrieve the installable APK through GitHub, open the [Holy Fitra Android APK workflow](https://github.com/niyasayem-glitch/holy-fitra/actions/workflows/android-app.yml), open a successful run on `master`, and download the artifact named `holyfitra-installable-debug-apk-<commit>`. It contains exactly `android-app-debug.apk`. The companion artifact `holyfitra-android-support-<commit>` contains the unsigned release APK, AAR, and native build outputs.

You can also select **Run workflow** on that page. Leave **Build and publish the debug-signed APK for direct installation** enabled, start the workflow, wait for the green result, open the run’s **Artifacts** section, and download `holyfitra-installable-debug-apk-<commit>`.

The Workbench requires no runtime permissions, account, network connection, or background service. It reports device capability, runs bounded native checks off the UI thread, persists the last local report, and shares a JSON report only after the user requests export.

## Build the APK yourself

A local Android SDK/NDK and Gradle installation are required. The project pins Android API 35, NDK `28.0.13004108`, CMake `3.22.1`, Java 17, and arm64-v8a:

```bash
gradle --no-daemon :android-app:assembleDebug
gradle --no-daemon :android-app:assembleRelease
adb install -r android-app/build/outputs/apk/debug/android-app-debug.apk
```

The release APK is unsigned unless a signing configuration is deliberately added by the deployer. CI verifies AArch64 ELF files, 16 KB PT_LOAD alignment, native library packaging, `c++_shared`, APK zip alignment, and debug signature validity.

## Verification and evidence

Run the complete host and Termux-compatible gate with:

```bash
bash termux-build.sh test --native-tests
python3 -m unittest -q
python3 validate_nibbleflow.py
python3 validate_holy_fitra_ragged.py
bash bootstrap/test_bootstrap.sh
```

Use `holyfitra capabilities` for the current implemented-feature and evidence-boundary report. Host and remote build gates do not prove physical-device execution, ART/JNI lifecycle behavior, NEON throughput, big.LITTLE scheduling, or thermal throttling. Those claims require an authorized physical ARM64 device and the separate device campaign harness.
